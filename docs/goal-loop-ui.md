# 单目标自主推进界面

默认创建界面只有「你想完成什么？」一个输入和「开始推进」。提交体默认严格为 `{goal}`，标题、隔离工作区和模型由平台决定；用户不需要填写 shell 命令或确认执行计划。高级设置保留可选模型、声明的 source ID 和明确的旧版手动任务模式，不接受新的任意目录作为自主目标来源。

自主目标详情显示真实阶段、执行轮次、失败反馈和只读共享验收方案。验收标准、固定检查、独立审查记录与 hash 在执行者/验证者之间共用；每轮结果保留 candidate、检查与原始证据。执行侧自检保留在折叠项中，不会当作独立通过。默认没有审批、手填命令或人工验收路径；停止/继续操作调度器，补充执行建议不改原始目标和固定标准。

Homelab、服务事件、其他插件工作区保持原导航。旧任务功能保留在折叠的高级控制中，其历史产物、执行记录和汇报仍可读取。

2026-10-11，TypeScript/生产构建通过；实际 Chromium 加模拟 API 的七项界面回归通过。新增回归检查单输入提交精确 `{goal}`、无审批/手填命令、暂停/继续/建议、固定标准和被拒成果反馈、每轮证明及 375px 无横向溢出。五项原有监控/插件/历史任务回归继续通过。这不是实际模型、自主目标或生产验收。

真实 GoalA/GoalB 验收待后端闭环、隔离验收服务和最终部署入口就绪后运行。准备好的只读浏览器检查要求显式指定已创建的任务 ID，不重复提交或手工 approve/accept：

```bash
REFBOX_LIVE_TEST=1 REFBOX_TEST_URL=https://refbox.jeffkafka.top \
REFBOX_GOAL_TEST_IDS=goal_a_id,goal_b_id REFBOX_GOAL_TEST_PASS_IDS=goal_a_id \
npm --workspace @refbox/web test -- --grep 'autonomous goals expose'
```

脚本读取原始目标和真实平台状态，核对固定标准 SHA-256、独立 reviewer/candidate/checks，查看原始证明，并检查键盘、手机和多插件导航；只发登录/退出请求，不改变目标状态。实际截图和 JSON 写入本地 `var/screenshots/`，不含认证数据。阻塞、失败和证据不足保持真实状态，不把自检成功当作闭环完成。
