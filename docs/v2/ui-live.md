## 生产入口


## 部署后的复测问题

19:33（Asia/Shanghai）复测中，历史产物请求超过八秒仍未响应，目标状态写入收到 Cloudflare 502 HTML 页面，页面明确为 Host Error。已保留响应状态和正文：`var/screenshots/live-http-failures-1791632041053.json`。当时公共首页 GET 为 200、0.184 秒，localhost `/health` 为 200、0.0006 秒；不能只用这两个健康检查判断完整用户路径稳定。

连接器日志显示 11:33:52 UTC 收到终止信号，11:33:57 重新启动，11:33:58/59 恢复两个连接；502 页面时间恰为 11:33:58 UTC。控制层没有同时重启。部署方确认这是自动修复策略对公共探针超时作出的连接器重启动作。随后修正默认策略并重新登记能力清单，公共网络探针超时不会默认触发连接器重启；Cloudflare 配置和 Tailscale 均未修改。

随后，取消默认连接器自动重启后的复测不再收到 5xx，但状态 POST 200 耗时 6.58 秒，紧接的全局快照与原生历史加载又各需数秒，原八秒界面断言提前耗尽。实测约 339 KB 全局快照，浏览器完整下载约 12–22 秒；当时 SSE 每两秒推送完整快照。这暴露了大数据帧传输与连续刷新的开销，而不是完成规则被拒绝。

前端现在立即使用状态/验收接口返回的真实任务反馈，历史和快照并行刷新；新增挂起快照的浏览器回归已通过。生产断言等待调整为 20 秒，保留 HTTP 成功、状态值、拒绝错误、刷新持久化与证据区分全部严格断言；模拟回归仍是八秒。控制层已部署压缩与仅变更时发送完整 SSE 帧。

生产测试现在能保留失败响应的时间、状态、Cloudflare Ray、正文和请求耗时/未完成状态，不保存请求头、Cookie、登录请求体或含密码的浏览器 trace。失败没有被跳过。
