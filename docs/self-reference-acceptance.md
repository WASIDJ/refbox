# 自指闭环真实验收（2026-10-11）

Refbox 是 Agent-native Homelab 的家与试验台。目标推进是其中一个基础模块；监控、独立插件工作区和其他个人长期服务仍共享控制层。此次实现先闭合最小的「目标 → 执行 → 独立检验 → 采用改进」流程。

用户只提交 `{goal}`。Pi Durable 负责实际规划与执行，另一进程、另一 Pi 数据库中的 Agent 审查公共验收方案并复核真实成果。宿主在独立 checkout 重跑固定测试、构建和浏览器检查，冻结既有测试、依赖清单及配置，并核对测试确实执行。执行自检成功只进入待验证；匹配 task、round、contract hash、candidate 的独立通过才能关闭业务目标。

采用 Matt Pocock 的 tracer bullet / TDD 方式：先固定可观察失败，再让系统完成一个小改进。每次独立通过后，外层验收编排器采用真实提交并重启隔离控制层，下一目标使用改进后的实现。部署仍由编排器负责，执行 Agent 不替换正在运行的验证器或服务。

固定测试 runner 同时运行冻结基线与候选新增测试。以新增故意失败的 Node 回归证明不会漏跑新测试；原测试和配置仍按基线哈希锁定。后台 Bash/Python 使用内部路径指向系统工具，避免外接 Homebrew 工具在启动阶段卡住。执行 Agent 使用只读内部 Wiki 缓存，测试使用隔离 Wiki 上下文，不读取用户的外接 vault。

生产构建与独立 Go runner 显式使用 `-buildvcs=true`。额外行为测试在独立 HOME 中设置 `buildvcs=false`，证明验收仍执行真实 VCS 测试，避免依赖用户的全局 Go 配置。执行者与验证者使用各自的 Go 缓存，后台工具链、默认源码和只读 Wiki 上下文存放内部盘。

完整公网验收还暴露了大证明的传输积压：线上目标 JSON 为 1,420,978 字节，本地读取约 9 毫秒，公网读取超过 32 秒；原生执行记录每 5 秒、快照每 15 秒继续轮询时，会让退出请求等待。任务与原生记录现在复用快照的 gzip 协商，完整证据不裁剪。前端同一记录只有一个在途读取，关闭详情取消读取，退出前取消快照、模型读取与实时连接；实时连接正常时不重复轮询快照。真实 HTTP 回归先复现未压缩的失败，再确认超过 1 MB 的 JSON 压缩后逐字节一致，并保留认证与拒绝 gzip 的行为。浏览器慢响应回归观察服务端连接关闭，先复现重复读取与关闭后仍有三条在途记录，再验证取消与退出，保留原有界面断言。

前端先读取完整快照，再使用其 SHA-256 建立实时连接；初始数据一致时只发送心跳。后续只传变化的顶层集合，客户端合并保留已有的完整证明，删除实体仍通过完整替换对应集合生效。旧客户端的完整 snapshot 协议保持兼容，指纹不匹配时重新同步完整权威快照。真实 HTTP 和浏览器回归验证了大证明保留、小资源变更、删除及失配恢复；不会把未变的原始证明随每次健康采样重复传输。
